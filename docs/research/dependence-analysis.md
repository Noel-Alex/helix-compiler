# Research digest: dependence analysis

_Verified August 2026 via parallel web research. Raw JSON: docs/research/raw/_

## Summary

Classical loop-dependence analysis is layered: normalize the loop, pair up memory references on the same base array, classify each pair RAW/WAR/WAW, and run a cheap-to-expensive "battery" of tests (ZIV, Strong/Weak-Zero/Weak-Crossing SIV, then GCD-MIV and Banerjee-MIV) where any test that succeeds proves independence; anything unproven is conservatively treated as a real dependence. Each test outputs refinement of a direction vector (<,=,>,*) and occasionally an exact distance vector; the dependence LEVEL (first non-"=" component) tells which loop it blocks, and a loop is DOALL-parallelizable iff no non-reduction dependence is carried at its level. LLVM's DependenceAnalysis.cpp is a direct, readable implementation of exactly this scheme (Goff/Kennedy/Tseng PLDI'91) and, together with LLVM's DDG doc (SCC "pi-blocks" mark recurrence cycles), provides the blueprint for a minimal per-nest dependence graph and a "Loop #N: RAW n / WAR n / WAW n => SAFE" report. For HELIX Lite's tiny subscript grammar (i, i+c, c-i, c*i; 2D i,j in one perfectly nested double loop) every test becomes exact closed-form arithmetic on widened (i64/i128) integers, with reductions (x = x (+,-,*,min,max) t) exempted as the only sanctioned distance-1 self-dependence. Anti/WAR and WAW dependences are storage-reuse artifacts eliminable by renaming/privatization/scalar-and-array expansion (mention-only in the report; your SSA IR already removes scalar false dependences).

## Key facts

1. Dependence taxonomy: flow/true (RAW) = earlier write, later read; anti (WAR) = earlier read, later write; output (WAW) = two writes; input (RAR) = two reads and NEVER blocks reordering or parallelization. Source = earlier access, sink = later access.
2. Distance vector d = integer iteration-count differences (sink iteration - source iteration) per nest level, e.g. for i=2..N: a[i]=a[i-1]+b[i] carries RAW a with distance <1>. Direction vector abstracts it to symbols < (d<0), = (d=0), > (d>0), * (unknown); Allen & Kennedy also use dependence level = position of leftmost non-'=' component (+1); all-'=' means loop-independent.
3. Core theorem (Allen & Kennedy Ch.2/Ch.4): a dependence is legal only if its distance/direction vector is lexicographically positive; loop L_k can run in parallel iff no dependence is CARRIED at level k (its first non-'=' entry is not at position k). This is the formal justification for '=> SAFE'.
4. GCD test (necessary condition, proves independence only): the Diophantine equation sum(c_k * i_k) = delta has an integer solution only if gcd(all coefficients) divides delta. It IGNORES loop bounds; passing it does NOT prove a dependence exists. Example: a[2*i]=a[i] -> i=2j, gcd(2,1)=1 divides 0, GCD inconclusive though dependences exist.
5. Banerjee test / inequalities ('Extreme Value Test', Wolfe Sec 2.5.2): for each direction, bound the subscript difference f(src)-g(dst) over the constrained iteration ranges; independence for a direction is proven iff 0 lies outside [L_min, U_max]. Necessary condition only. Worked Wikipedia example: for(i=0;i<10;i++){c[i+9]=a[i]+b[i]; d[i]=c[i]+e[i];} gives antidependence broken (1 <= -9 <= 9 fails) but true dependence not broken (-9 <= -9 <= 0 holds) => parallelizable with statements kept in order.
6. SIV battery (subscript-by-subscript, exact when each subscript holds <=1 index variable; from Goff/Kennedy/Tseng 'Practical Dependence Testing' PLDI'91 pp.15-29): ZIV (constants both sides: dep iff equal, direction '='); Strong SIV (a*i+p = a*i'+q: distance d=(q-p)/a if divisible else INDEPENDENT; direction from sign of d); Weak-Zero SIV (a*i+p = c: single point i*=(c-p)/a must be integral and inside [L,U]; LLVM refines to '<=' when it hits the first iteration and '>=' when it hits the last); Weak-Crossing SIV (a*i+p = -a*i'+q: crossing x=(q-p)/(2a); integral+in-bounds permits BOTH '<' and '>', odd numerator kills '=', non-integral/out-of-bounds proves independence). MIV (multiple index vars) falls back to GCD-MIV then Banerjee-MIV.
7. Per-dimension combination rule: results are conjoined; ONE dimension proving independence kills the whole multidimensional dependence; surviving direction vectors intersect componentwise; distance vector is known only when every component is uniquely determined.
8. Ordering constraints per pair: distinct statements s1-before-s2 allow (i==j, s1<s2) [loop-independent dep] OR i<j [carried]; same statement requires strict i<j. Address equality must hold in EVERY dimension simultaneously.
9. LLVM implementation facts (verified in llvm/lib/Analysis/DependenceAnalysis.cpp @ main, Aug 2026): header states it is an incomplete implementation of Goff/Kennedy/Tseng PLDI'91; functions strongSIVtest, weakZeroSIVtestImpl, weakCrossingSIVtest, gcdMIVtest, banerjeeMIVtest; each returns true == 'dependence disproved'; FullDependence result carries per-level DV{Distance, Direction} bitflags LT/EQ/GT; strong SIV computes Delta=sdivrem(DstStart-SrcStart, Coeff) and maps remainder!=0 to independence; Banerjee widens ALL arithmetic to WideBits = 2*BaseBits + MaxLevels + 1 bits to prevent bound-computation overflow, and uses backedge-taken counts as bounds ('a single-iteration loop has bound 0, making < and > impossible'); gcd-MIV additionally tries to disprove '=' per level (Wolfe book p.235 technique); delinearization (-da-delinearize) recovers multi-dim subscripts from flattened C arrays.
10. LLVM DDG structure (llvm/docs/DependenceGraphs/index.rst, verified): nodes = instructions (grouped into multi-instruction nodes), memory edges carry flow/anti/output/input deps, strongly-connected components become one-level-deep 'pi-blocks' representing recurrence cycles that block reordering; built via DependenceGraphBuilder builder-pattern (cites Kuck/Kuhn/Padua/Leasure/Wolfe POPL'81 and Ferrante/Ottenstein/Warren PDG TOPLAS'87). NOTE: the old llvm.org/docs/DependenceAnalysis.html URL currently returns 404 - the page was removed from the docs tree while DependenceAnalysis.cpp still ships; cite the source file instead.
11. GCC comparison point: parloops/-ftree-parallelize-loops=n performs automatic loop parallelization gated by dependence proof; the isl-based Graphite framework became default-on at -O3/-Ofast/-Os in GCC 15 (2025) and remains present in GCC 16 trunk (not removed). Polly (LLVM) does exact dependence relations via ISL for comparison in your report.
12. Reduction recognition rules: scalar x is a reduction iff x appears on both sides as exactly x = x op t or x = t op x with op associative (and commutative), written once per iteration, no OTHER reads/writes of x in the body, the ONLY cross-iteration dependence touching x is that self-dependence (typically distance 1); then give each thread a private accumulator seeded with the identity (+:0, *:1, min:+MAX/+inf, max:-MIN/-inf) and combine after join; copy the final value out afterward (OpenMP 'lastprivate'-like semantics). OpenMP supports reduction ops +,-,*,&,|,^,&&,||,max,min for C/C++ (max/min since OpenMP 3.1). FLOATING-POINT +/* are NOT associative (f32/f64): reassociation changes rounding - gate behind a fast-math-style flag or warn, matching what icc/gcc/clang document.
13. Same-statement different-subscript case: a[i]=a[i-1]+1 -> store a[i] (src) vs load a[i-1] (sink): Strong SIV gives d=(0-(-1))/1=1 => distance-1 RAW carried at level 1 => loop must stay serial (DOACROSS/hyperplane only). Contrast a[i]=b[i]+1: all deps loop-independent => DOALL-safe. Reduction contrast: s+=a[i] looks like distance-1 RAW on s but is exempt via reduction recognition.
14. HELIX-Lite-sized exact algorithm (all subscripts affine in one index per dim): normalize loop to i in [L,U], N=U-L+1>=1; do ALL subscript/bound arithmetic in i64 (or i128), never in the element's width; per dimension dispatch: ZIV exact; Strong SIV exact (divisibility + bounds check i, i+d in [L,U]); Weak-Zero SIV exact (integral point in range); Weak-Crossing SIV exact (crossing point); general unequal-coefficient case like a[c*i] vs a[i] (c!=1): solve a*i-b*j=k, let g=gcd(a,b); k%g!=0 => none, else parametric solutions i=i0+(b/g)t, j=j0+(a/g)t intersected with the [L,U]^2 box - empty box proves independence, nonempty yields direction '*' (optionally compute minimum positive distance by ceil/floor on t); nonlinear/unknown => assume dep '*'. Any dimension NO-DEP => no dependence; else emit (kind, level, distance-or-direction). Verdict SAFE-for-level-k iff no emitted RAW/WAR/WAW has level k after reduction exemptions.
15. Report shape mirroring real tools: per nest emit 'Loop #N (file:line): depth 2'; then one line per candidate pair 'a[] : S1(store)->S2(load) RAW dist=<1> dir=< > level=1'; finish with 'Loop #N: RAW 0 / WAR 0 / WAW 0 => SAFE (parallelize, k threads)' or '=> SEQUENTIAL (RAW carried at level 1)' / '=> REDUCTION (+ on s) => PARALLEL with private accumulators'.
16. Elimination of false dependences (mention-only material): anti(WAR)+output(WAW) come from STORAGE REUSE, not dataflow (Kuck/Padua lineage); renaming kills them for scalars - HELIX's SSA IR already eliminates scalar anti/WAW by construction, which is worth stating explicitly in the report; remaining techniques: scalar expansion (s -> s[i] array so each iteration writes its own slot), array expansion / privatization (per-thread private copy of an array or section; correctness needs first-iteration reads to see the original values and final-value propagation for last-private semantics), OpenMP private/firstprivate/lastprivate clauses as the user-directed equivalent (Allen & Kennedy Ch.3; Wolfe Ch. on eliminating dependences).
17. Current toolchain versions checked on crates.io (Aug 2026): cranelift, cranelift-codegen, cranelift-native, cranelift-jit all at 0.135.0; rayon 1.12.0. std::thread::scope (stable since Rust 1.63) is sufficient to fan a JIT-ed kernel out over ~32 logical CPUs by slicing the array into chunks and joining partial results; finalize_definitions() must complete before threads spawn, and calling finalized functions concurrently afterwards is supported.

## Recommendations

1. Implement exactly four exact per-dimension tests in this order and stop at the first independence proof: ZIV, Strong SIV, Weak-Zero SIV, Weak-Crossing SIV; add the bounded-Diophantine general case (a*i-b*j=k with box intersection) only for mismatched coefficients like a[2i] vs a[i]. Skip Omega/polyhedral entirely and say so in the report - for your subscript grammar everything above is EXACT, which is a stronger claim than production compilers usually get to make.
2. Adopt LLVM's return-convention internally: every test returns 'disproved/independent?' bool and writes refinements (distance, direction bits) into a shared FullDependence-like struct with per-level {Distance: Option<i64>, Direction: {LT,EQ,GT} bitset}. This makes the code mirror the paper and makes unit tests trivial.
3. Perform ALL analysis arithmetic in i64 (consider i128 for c*i terms and Banerjee-style bounds), regardless of whether elements are i32/f32 - LLVM explicitly widens to 2B+levels+1 bits for this reason; document the choice in the report as overflow-safety of the ANALYZER itself.
4. Model dependences as a small per-nest graph: node per statement, edge annotated {kind RAW/WAR/WAW, base array, level, distance: Option<i64>, dirs}. Run SCC; a cycle = serial loop UNLESS every cycle edge is a recognized reduction self-loop. Then print 'Loop #N: RAW n / WAR n / WAW n => SAFE/SEQUENTIAL' from edge counts at the target level.
5. Handle the three canonical teaching examples as golden tests: (1) a[i]=a[i-1]+1 -> RAW dist 1 => sequential; (2) a[i]=b[i]*2 -> no same-array pair => SAFE; (3) s+=a[i] -> reduction exemption => SAFE-with-reduction. Add a[2i]=a[i] (GCD inconclusive, exact box test decides) and a[i][j]=a[i][j-1]*x (level-2 carried) as 2D cases.
6. Reduction recognition checklist to enforce: single assignment to x per iteration of the form x=x op t or x=t op x; op in {+,-,*,min,max}; no other references to x in the body; seed private accumulators with identities (0,0,1,+MAX,+MIN) and merge after join; propagate final value back. Emit a WARNING (not silence) when x is f32/f64 and op is + or * because reassociation changes rounding; offer a fast-math-style language flag to permit it.
7. Treat RAR (input) dependences as always-ignorable and SAY SO in the report; many student implementations wrongly block on them.
8. State in the report that HELIX's SSA form already removes scalar anti/WAW dependences by construction (renaming), so only ARRAY false dependences (WAR/WAW through [T]) can ever force serialization - that is a clean, true observation tying your IR to Allen & Kennedy Ch.3, with privatization/array-expansion described qualitatively as future work.
9. Bound every test with trip counts: require N=U-L+1 >= 1, clamp/verify source and sink indices against [L,U] after computing distances (LLVM's insight that a single-trip loop cannot carry a '<' or '>' dependence is a nice extra check that catches off-by-one bugs).
10. Use std::thread::scope with chunks_mut() sized len/num_cpus (std::thread::available_parallelism()) rather than pulling rayon, to keep the dependency story of a course project minimal; rayon 1.12.0 par_chunks_mut is the drop-in alternative if you want work-stealing; compile the kernel with cranelift-jit 0.135.0, finalize before spawning, and pass raw chunk pointers as extern "C" fn(*mut T, usize).

## Pitfalls

1. Sign-convention bugs on distance/direction: some texts define d = i_sink - i_source, others (LLVM's Delta = Src-Dst) invert it and then map positive distance to LT; pick ONE convention, write it in a comment, and unit-test a[i-1] (WAR-looking but actually RAW dist +1) vs a[i+1] (dist -1, i.e. a backward 'anti-flow' pattern) - mixing conventions silently flips SAFE/UNSAFE verdicts.
2. Forgetting loop bounds entirely: the GCD test alone ignores them, so a[i] vs a[100] in a 10-trip loop looks dependent; conversely Banerjee bounds computed with the wrong max index (trip count N vs last index N-1 vs LLVM's backedge-taken count) produce off-by-one independence proofs that are UNSOUND, not just imprecise. A single-trip loop must never yield a '<' or '>' direction.
3. Treating a PASSED test as proof of dependence: GCD and Banerjee are necessary conditions - passing means 'unknown', failing means 'independent'. Reporting 'dep found because gcd divides delta' is the classic inversion error.
4. Unsigned/wraparound mishandling: in Rust, debug builds PANIC on i32 overflow while release builds WRAP silently (overflow-checks profile flag), and in C signed overflow is UB (compilers exploit no-wrap assumptions; -fwrapv disables). If your front-end lets index expressions overflow, monotonicity arguments behind SIV distance math break; compute analysis in wider ints and decide explicitly whether HELIX source arithmetic wraps (document it; consider wrapping_mul/wrapping_add semantics or rejecting overflowing constant folds).
5. Applying separable (SIV) tests to coupled subscripts: a[i][j] vs a[j][i] must NOT be tested dimension-by-dimension with SIV logic as if dimensions were independent - coupled subscripts need the MIV fallback or a conservative '*'; silently misclassifying them produces wrong SAFE verdicts.
6. Dropping the conjunctive combination rule: a multidimensional pair is independent if ANY dimension is disproved; students sometimes require all dimensions to disprove (over-serializing) or forget to intersect surviving direction vectors componentwise (under-serializing).
7. Ignoring intra-iteration ordering: for distinct statements you must allow (same iteration + statement order) as a valid loop-independent dependence; for same-statement pairs you must REQUIRE strictly increasing iterations. Getting lexicographic order wrong turns a[i]=b[i]+a[i-1] into nonsense.
8. Reduction over-recognition: accepting x = x op y when x has OTHER reads/writes elsewhere in the body, when the op chain isn't a single associative fold (e.g. x = (x+a)*b), or ignoring float non-associativity - each silently changes program results. Also remember min/max identity values and post-loop final-value propagation.
9. Assuming unit stride or known trip counts: guard with a runtime check (or bail to sequential) when N<=0 or when bounds are symbolic and the divisibility/interval arguments can't be made; LLVM adds explicit SCEV predicates/runtime assumptions for exactly this reason (e.g. proving coefficient != 0 before concluding '=' direction in strong SIV).
10. Alias/base-array confusion: the analysis is only sound because HELIX arrays are values with no aliasing; the moment you add pointers or slices-as-views, same-base-name checks stop being sufficient - note this limitation in the report instead of discovering it as a bug.
11. Overflow INSIDE the analyzer: evaluating c*i or bound sums in i32 can wrap and flip an independence proof; this is precisely why LLVM widens Banerjee arithmetic to 2B+levels+1 bits.
