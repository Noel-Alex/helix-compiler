# Research digest: language spec review

_Verified August 2026 via parallel web research. Raw JSON: docs/research/raw/_

## Summary

The HELIX Lite sketch is fundamentally sound for its goals (SSA scalar opts, affine dependence analysis, Cranelift JIT), but it is underspecified in roughly a dozen places that will cause rework during typechecking and codegen if frozen as-is. Recommended freeze: zero implicit coercions (with one pragmatic exception — array-index widening to i64), i64 as the sole arithmetic integer with i32 as a storage-only array element type, mandatory braces (kills dangling-else), ranges restricted to for-headers only, checked-by-default semantics (bounds, div-by-zero) implemented as explicit guarded branches rather than native faults, and a 7-builtin stdlib (print, zeros, len, abs, sqrt, min, max) that covers matmul/Mandelbrot/N-body/sieve/reduction demos. Cranelift maps cleanly onto these choices: `%` is srem (sign of dividend), `/` is sdiv (traps /0 and INT_MIN/-1), float-to-int casts use fcvt_to_int_sat semantics (NaN→0, saturate), and sqrt/fabs are first-class instructions. Pin one cranelift crate family (current line ~0.135.x, Aug 2026) since wasmtime ships several majors in lockstep.

## Key facts

1. Cranelift version landscape (verified Aug 2026): cranelift-jit newest_version 0.123.14 on an older maintained train but max_stable_version 0.135.0 (last publish 2026-08-20); docs.rs currently documents cranelift-frontend 0.134.3; wasmtime shows newest_version 36.0.14 vs max_stable_version 48.0.0 — multiple release trains ship in parallel, so pin an exact minor family (e.g. cranelift = "0.135") rather than a loose caret.
2. cranelift-frontend API surface confirmed current and non-deprecated: FunctionBuilder (declare_var/def_var/use_var), FunctionBuilderContext, Variable — Variable-based mutable variables are auto-converted to SSA, which exactly matches HELIX's 'mutable scalars via reassignment' model; Switch struct exists for later switch lowering.
3. Cranelift sdiv traps on divisor==zero AND on INT_MIN/-1 ('result not representable'); it is formally a cannot-speculate trapping instruction (IntDivTrap::{Zero,Overflow} in codegen/src/ir/instructions.rs). On x64 idiv faults natively; on AArch64 Cranelift inserts explicit guard branches.
4. Cranelift srem is truncated remainder: result has the SIGN OF THE DIVIDEND (matches C/Rust % and Python's // pairing), undefined for /0 and INT_MIN/-1. smod is floored modulo with sign of the DIVISOR (Python % style). HELIX '%' should be specced as srem semantics: -7 % 2 == -1, 7 % -2 == 1.
5. Cranelift fmin/fmax are specified IEEE 754-2008 minNum/maxNum: if exactly one operand is NaN, return the OTHER operand; NaN only if both are NaN. Known implementation hazard rust-lang/rust#9903: naive lowering via x86 MINSS/MAXSS propagates NaN from either operand. Relevant if HELIX min/max builtins or reductions are lowered to fmin/fmax — verify or use select(fcmp ord)-style sequences.
6. fcvt_to_int_sat / fcvt_to_uint_sat (i32/i64 variants): NaN becomes 0, out-of-range saturates to MIN/MAX incl. infinities — identical to Rust's `as` cast semantics standardized in Rust 1.45 (RFC 2535). Non-saturating fcvt_to_int is UB when the value does not fit. Use the _sat forms so interpreter and JIT agree bit-for-bit.
7. sqrt.f32/.f64 is a first-class deterministic IEEE instruction (NaN for negative input); fabs and copysign are bitwise-sign instructions. There is NO pow/exp/log instruction in Cranelift — anything beyond sqrt must come from libm FFI or polynomial demos.
8. Bounds/div-zero strategy constraint: cranelift-jit is officially 'not intended for production yet'; Windows x64 IS a supported ISA target, and the historic >2GB VirtualAlloc(MEM_COMMIT) limitation on Windows was fixed via MEM_RESERVE (wasmtime issue #523), but relying on native divide faults for language-level errors means catching them through Windows SEH/vectored exception handlers — fragile under a JIT. Explicit compare-and-call-panic-guard codegen is portable and teachable.
9. Rust precedent worth citing in the reference appendix: float->int `as` casts round toward zero, NaN->0, saturation at type limits (doc.rust-lang.org/reference, 'numeric cast'); Rust `%` is truncated remainder matching Cranelift srem; Rust requires braces and has no dangling-else, which is the style HELIX should copy.

## Recommendations

1. BUILTINS — freeze exactly 7: print(e) (any scalar, or [T] printed as '[v0, v1, ...]' on one line; returns unit); zeros(n) -> [T] with element type inferred from the annotated binding (requires `let a: [f64] = zeros(n);`); len(a) -> i64; abs(x) (same numeric type back); sqrt(x) (f32->f32, f64->f64, negative input = NaN per IEEE); min(a,b)/max(a,b) (same-type numerics, IEEE minNum/maxNum NaN rule: non-NaN wins). Nothing else. This set runs matmul, Mandelbrot (iteration counts, no math builtins needed), N-body (sqrt), prime sieve (zeros+[bool]), dot-product/reduction parallelization showcases, and histograms — the smallest set that demos beautifully. Deliberately exclude: pow/exp/log (no Cranelift instruction; would force libm FFI plumbing), floor/ceil, string formatting, input(), a separate println (print always appends newline).
2. GRAMMAR — adopt the EBNF below verbatim. Key closure decisions: (1) comments // to end-of-line and /* */ block comments, NON-nested (C-style; note divergence from Rust explicitly); (2) unary ops are - and !, binding tighter than * / %; (3) six precedence levels, all binary left-associative: || < && < == != < < > <= >= < + - < * / % < unary < postfix(index/call) < primary; `as` casts bind tighter than unary minus (-x as i32 parses as -(x as i32)); parentheses group; (4) && and || SHORT-CIRCUIT mandatorily and desugar to branch diamonds in your CFG IR — this is a selling-point exercise, not overhead; (5) ranges appear ONLY in for headers: `for i in e1..e2` half-open [e1,e2), no step clause in v1 (reserve keyword `by`; add strided form only when a tiling demo actually needs it), no `..=` inclusive form, ranges are NOT first-class values; (6) else-if chains fall out of `else (if-stmt | block)` recursion; BRACES MANDATORY on every if/for body — eliminates dangling-else by construction; (7) nested functions DISALLOWED (flat global function table, trivial name resolution); recursion ALLOWED (fib/factorial demos; free via native Cranelift call lowering); multiple return values NO; early return YES — lowers to a branch on a dedicated exit block holding the single return value, a clean SSA/phi lesson; (8) assignment is a STATEMENT, not an expression — kills `a=b=c` and the `if x=y` typo class; (9) reserve now, implement later: while, break, continue, mut, in, as (used), true/false (used), and, or, not, struct, import.
3. TYPES — zero implicit coercions between int and float; the ONLY sanctioned implicit conversion is array INDEX i32->i64 widening (students write `a[i]` with i32 counters constantly; forcing `as` there poisons ergonomics for no pedagogical gain). Integers: make i64 the one arithmetic integer — unannotated integer literals infer i64; i32 exists purely as an array element/storage type for cache-bandwidth demos; mixing i32 and i64 VALUES in an operator requires an explicit `as` cast. Evaluate-and-reject alternative: automatic i32->i64 promotion everywhere — it doubles the checker rules and the number of Cranelift value types you juggle for zero demo benefit. Bool: NO truthiness, conditions must be typed bool, no int<->bool coercion, `!` is the only bool op besides comparisons. Arrays: element types must match exactly for assignment/passing; arrays are fat pointers (base+len), passed by REFERENCE so callee writes escape (write this sentence into the spec verbatim — it is the load-bearing semantic for your escape demos); arrays are not copyable; NESTED ARRAYS FORBIDDEN in v1 ([T] where T is scalar only) — flat arrays keep subscript analysis affine and LICM sound; matrices are done with manual r*n+c indexing (good for the dependence-analysis narrative). Unit type: spelled (), procedures are `fn f(...)` with no arrow or `-> ()`; calling a unit function inside an expression is a static error; `return;` vs `return expr;` distinguished by declared return type.
4. SEMANTICS — freeze these five policies: (1) integer / and % by zero AND i64::MIN / -1 or % -1 are RUNTIME ERRORS with a source-location message in the interpreter; in JIT codegen emit an explicit guard (compare divisor to 0, branch to a panic stub) before sdiv/srem — do NOT rely on native x86 #DE faults, because converting those into clean errors under cranelift-jit on Windows means fighting SEH/vectored handlers; one extra branch per division is negligible and portable. (2) Signed integer OVERFLOW elsewhere is defined two's-complement WRAPPING (document it; consistent with choosing not to trap on abs(i64::MIN), which should also wrap). (3) Floats are full IEEE: NaN and +/-Inf flow through arithmetic, float division by zero produces Inf/NaN (never traps), print renders 'nan'/'inf'. (4) Array bounds are CHECKED BY DEFAULT in both interpreter and JIT (same compare-and-trap pattern); provide --unchecked to strip checks for perf-comparison benchmarks and state plainly that OOB access under --unchecked is UB and may crash. This checked-vs-unchecked delta is itself a great lab measurement of safety cost. (5) DEFINITE ASSIGNMENT is enforced statically by a dataflow pass (every variable initialized on all paths to a use; arrays come pre-initialized from zeros) — it doubles as the warm-up for your liveness/DCE passes. Out-parameter convention: NONE — one return value plus array-reference mutation is the only multi-output idiom (write results into a caller-supplied output array).
5. ENTRY POINT — require exactly one `fn main()` with zero parameters returning unit; the driver looks it up in the function table and errors if missing/duplicated. PROGRAM-LEVEL STATEMENTS FORBIDDEN: the top level contains only fn definitions and optionally `const NAME: type = literal;` scalar constants (useful for shared problem sizes like `const N: i64 = 1024;`; forbid const arrays in v1). This keeps the module layout = a flat symbol table, which is all Cranelift's Module/JITBuilder needs anyway (one cranelift_function per fn, main invoked through a typed function pointer signature () -> ()).
6. PARALLELIZATION-FACING SPEC SENTENCES (write them now so the language reference and the optimizer chapter stay consistent): (a) for-loop bodies must not reassign the loop variable (statically rejected) — guarantees affine iteration space; (b) print is a side effect and a loop containing print is never parallelized — otherwise parallel output ordering destroys demo credibility; (c) passing the SAME array variable as two arguments of one call (f(a, a)) is statically rejected — cheap syntactic check that protects your loop-carried-dependence analysis from aliasing it cannot see; (d) reductions recognized for +, -, *, min, max accumulate into a single scalar accumulator matching the canonical `acc = acc op a[i]` shape.
7. PROPOSED EBNF (freeze-ready, sized for the appendix): program ::= { fn_def | const_def }; fn_def ::= 'fn' IDENT '(' [param {',' param}] ')' ['->' type] block; const_def ::= 'const' IDENT ':' type '=' literal ';'; param ::= IDENT ':' type; type ::= 'i32'|'i64'|'f32'|'f64'|'bool'|'[' scalar_type ']'|'()' ; scalar_type ::= 'i32'|'i64'|'f32'|'f64'|'bool'; block ::= '{' {stmt} '}'; stmt ::= let_stmt | assign_stmt | if_stmt | for_stmt | return_stmt | expr ';' | ';' | block; let_stmt ::= 'let' IDENT [':' type] '=' expr ';'; assign_stmt ::= lvalue '=' expr ';'; lvalue ::= IDENT ['[' expr ']']; if_stmt ::= 'if' expr block {'else' (if_stmt | block)}; for_stmt ::= 'for' IDENT 'in' expr '..' expr block; return_stmt ::= 'return' [expr] ';'; expr ::= or_expr; or_expr ::= and_expr {'||' and_expr}; and_expr ::= eq_expr {'&&' eq_expr}; eq_expr ::= rel_expr {('=='|'!=') rel_expr}; rel_expr ::= add_expr {('<'|'>'|'<='|'>=') add_expr}; add_expr ::= mul_expr {('+'|'-') mul_expr}; mul_expr ::= unary_expr {('*'|'/'|'%') unary_expr}; unary_expr ::= ('-'|'!') unary_expr | cast_expr; cast_expr ::= postfix {'as' scalar_type}; postfix ::= primary ['[' expr ']'] | primary ['(' [expr {',' expr}] ')']; primary ::= literal | IDENT | '(' expr ')'; literal ::= INT_LIT | FLOAT_LIT | 'true' | 'false'. Lexer: comment ::= '//' {!NEWLINE} | '/*' {!'*/'} '*/' (non-nested).
8. TYPE-RULE TABLE (appendix-ready): arith +,-,* : both operands same numeric type -> that type; / : ints -> same int type, traps /0 and INT_MIN/-1; floats -> IEEE quotient; % : ints only, srem semantics (sign follows dividend), traps same as /; unary - : numeric -> same; comparisons < > <= >= : same numeric type -> bool; == != : same scalar type -> bool (arrays NOT comparable); && || : bool,bool short-circuit -> bool; ! : bool -> bool; a[i] : a:[T], i:i32-or-i64 (widened to i64) -> T, bounds-checked; f(args) : exact parameter types (index-widening excepted) -> declared return type; x as T : numeric->numeric only (bool excluded, arrays excluded), fcvt_to_int_sat semantics for float->int (NaN->0, saturate); zeros(n) : n:i64 (or i32 widened) -> [T], T from annotation; len(a) : a:[T] -> i64; print(e) : any -> ().

## Pitfalls

1. Relying on native divide faults (x86 #DE) for div-by-zero errors: under cranelift-jit on Windows this surfaces as an OS exception needing vectored exception handling to report cleanly — fragile and platform-specific. Always emit explicit compare-and-branch guards to a panic stub, uniformly for div-by-zero, INT_MIN/-1, and bounds checks.
2. % sign confusion: Cranelift srem (HELIX '%') follows the DIVIDEND's sign (-7 % 2 == -1) while students arriving from Python expect floored modulo (-7 % 2 == 1). Put a worked example in the reference or this generates bug reports all semester. Do not be tempted to expose smod too.
3. If you lower min/max builtins or reductions straight to Cranelift fmin/fmax, remember the documented IEEE minNum/maxNum contract (non-NaN operand wins) differs from what x86 MINSS/MAXSS naively produce (either-side NaN propagation) — the exact discrepancy behind rust-lang/rust#9903. Test min/max with NaN inputs, or build them from select+ordered-compare.
4. Float->int casts must use saturating semantics (fcvt_to_int_sat: NaN->0, clamp at limits) in BOTH interpreter and JIT. Using plain fcvt_to_int is UB on out-of-range values and WILL diverge between your tree-walking interpreter and generated code — a nightmare debugging scenario in a course setting.
5. Version pinning: wasmtime/Cranelift publishes multiple major trains simultaneously (36.x patches shipping alongside 48.0.0 as of Aug 2026) and cranelift-jit is labeled experimental/'not intended for production'. Lock Cargo.toml to one exact 0.13x family and record it in the reference; blind caret upgrades can change legalization behavior mid-semester.
6. Implicit int->float coercion would quietly poison reduction recognition and dependence classification (int += is associative-integer-exact, float += is NOT associativity-safe) — one more reason the zero-coercion recommendation is load-bearing, not just aesthetic. If anyone re-litigates coercions, route them to the parallelization argument.
7. Nested arrays ([[T]]) or array copy-on-pass would break the flat affine subscript model and the 'writes escape' demos respectively. Freeze '[T] where T is scalar' and fat-pointer reference passing as non-negotiable; also reject duplicate-array-argument calls f(a, a) statically or your independence proof silently assumes away aliasing.
8. Allowing ranges as ordinary values (or a step/inclusive form) prematurely drags in a range type, iteration-protocol design, and heap allocation — none of which serve the optimization storyline. Restrict '..' syntactically to for headers; the grammar production above enforces it for free.
9. Braceless if/for bodies reintroduce the dangling-else ambiguity and special-case parser recovery for zero benefit. Mandatory braces (Rust/Go style) is the correct freeze.
10. print inside parallelizable loops: unless the spec states that side effects block parallelization, students will see scrambled output and conclude the parallelizer is broken. State it explicitly, and consider having the compiler PRINT a notice ('loop L not parallelized: contains side effect') — turns a pitfall into a feature demo.
11. Unit-returning functions used as expressions must be a hard type error; if tolerated, you get silent zero-values flowing through DCE and confusing optimizer traces.
12. Missing definite-assignment enforcement shows up as nondeterministic garbage in JIT runs that benchmarks 'great' — enforce it statically before any performance work, and reuse the pass as your liveness-analysis teaching example.
