# Research digest: ssa design

_Verified August 2026 via parallel web research. Raw JSON: docs/research/raw/_

## Summary

For HELIX Lite, compute dominators with the Cooper-Harvey-Kennedy iterative immediate-dominator algorithm (roughly 80 lines, near-linear in practice) rather than Lengauer-Tarjan, derive dominance frontiers directly from the idom array, and build semi-pruned SSA by placing phis at the iterated dominance frontier of "global" variables (those with upward-exposed uses), renamed via a dominator-tree preorder walk. Keep SSA strictly scalar and leave [T] arrays as explicit load/store operations - this is the standard LLVM/GCC/Cytron precedent and is exactly what affine-subscript dependence analysis wants. Do not implement classical out-of-SSA translation at all: Cranelift IR is SSA with block parameters that are semantically phis whose arguments each predecessor terminator passes explicitly, so HELIX phis lower 1:1 to block params and the lost-copy/swap problems become regalloc2's move-coalescing job. Current crates are cranelift-codegen/-frontend/-jit 0.135.0 (published 2026-08-20, with concurrent maintenance lines 0.134.x/0.133.x/etc., so pin exact versions).

## Key facts

1. Cooper-Harvey-Kennedy ('A Simple, Fast Dominance Algorithm', Rice): compute postorder via DFS from entry, process blocks in REVERSE postorder; idom[entry]=entry (self-sentinel), all others UNDEFINED; repeat until no change: for each b in RPO (skip entry), take first pred with idom set as new_idom, then for every other processed pred p: new_idom <- intersect(p, new_idom); write back if changed.
2. CHK intersect(b1,b2): two fingers start at b1,b2; while fingers differ, whichever has the SMALLER postorder number is replaced by its idom (higher postorder number = closer to root); returns the meeting node. Empirically near-linear, slightly superlinear worst case; the paper shows it competitive with tuned Lengauer-Tarjan while being dramatically simpler.
3. Verdict for a small project: CHK fits. Lengauer-Tarjan variants (semi-NCA/hybrid) matter for LLVM/GCC because real-world CFGs reach tens of thousands of blocks; for course-scale functions CHK is faster to write, easy to verify, and its idom array directly feeds DF computation, dominator-tree walks, and dominance queries used by CSE/LICM/verification.
4. Dominance frontiers from idoms, runner form (simplest, needs only the idom array): for every join b with >=2 predecessors, for each pred p: runner=p; while runner != idom[b]: { DF[runner].insert(b); runner = idom[runner]; }
5. Equivalent Cytron bottom-up form (TOPLAS 1991): DF(X) = DFlocal(X) UNION union over children Z of DFup(Z), where DFlocal(X)={Y in succ(X) : idom(Y)!=X} and DFup(Z)={Y in DF(Z) : idom(Y)!=X}; traverse the dominator tree children-first. Worst case O(E+N^2), usually linear because DF sets are small.
6. SSA flavor taxonomy: MINIMAL = phis at iterated DF of every def site, no liveness; SEMI-PRUNED (Briggs, Cooper, Harvey, Simpson, SP&E 28(8), 1998) = restrict phi insertion to 'global' names found by one linear pass computing per-block local-def sets and upward-exposed uses (UEVar); PRUNED (Choi, Cytron, Ferrante 1991) = additionally require the variable be live-in at the join, which costs a full block-level backward liveness fixpoint (UEVar/Kill per block, iterate to fixpoint).
7. Briggs et al.'s measurements: semi-pruned yields phi counts close to pruned at a fraction of the cost - it is the accepted sweet spot for hand-written compilers; pruned machinery (full liveness) buys little unless dead phis measurably slow later passes.
8. Renaming step (all flavors): preorder walk of the dominator tree carrying per-variable stacks of current SSA names; push on defs and phis, pop on exit, fill phi arguments when visiting successors (or afterwards by scanning each pred). Parameters and zero-initialized globals must be seeded as entry-block definitions so every use has a reaching def.
9. Alternative construction style: Braun, Buchwald, Hack, Leissa, Mallon, Zwinkau, 'Simple and Efficient Construction of Static Single Assignment Form' (CC 2013, arXiv:1211.3688) builds PRUNED SSA on-the-fly during AST->IR translation using readVariable/writeVariable, sealed/unsealed blocks for forward refs and back edges, and lazy phi creation with trivial-phi elimination. This is what cranelift-frontend's FunctionBuilder implements (its docs cite Braun et al.); relevant only if you generated straight to CLIF, which conflicts with running your own optimizer on your own IR.
10. Out-of-SSA destruction theory: naive phi-to-copy rewriting hits (a) the LOST-COPY problem - a value whose live range a phi split dies at the inserted copy but is still needed along another path (typically loops), and (b) the SWAP problem - parallel copies forming cycles (a,b <- b,a) produce wrong results if executed sequentially without temporaries. Canonical treatments: Sreedhar, Ju, Gillies, Santhanam (SAS'99, LNCS 1694 pp.194-210); Budimlic, Cooper, Harvey, Kennedy, Mergen, Reeves, Tian (CGO 2005); Briggs et al. 1998 section 4; textbook treatment in Rastello & Bouchez Tichadou, 'SSA-Based Compiler Design'. All require interference graphs or parallel-copy sequentialization with temp-based cycle breaking - significant machinery.
11. Cranelift block params: basic blocks carry parameters that ARE phis semantically; the value is selected by which incoming edge was taken. Invariant enforced by Cranelift's verifier: every terminator targeting block B (jump, brif arm, br_table arm) must pass EXACTLY len(params(B)) arguments, type-matched positionally; different predecessors may pass different values but never different arity/types. brif carries two independent argument lists (then-target and else-target).
12. Consequence: you can skip destruction entirely. For each HELIX block with k phis: create the CLIF block and issue k append_block_param calls in a fixed order; every predecessor terminator supplies its k values aligned to that order. regalloc2 merges the liveranges on either side of a block parameter into one bundle / coalesces the moves (Chris Fallin's regalloc2 write-up, 2022), so swap cycles and lost copies are resolved inside Cranelift's allocator, not in your code.
13. Scalar-only SSA precedent: Cytron et al. 1991 defines SSA over scalars; LLVM keeps register values in SSA while memory is deliberately outside SSA - mem2reg promotes only scalar allocas whose sole uses are load/store (default threshold 64 bytes), arrays indexed via GEP are never promoted, and SROA splits only aggregates with statically identifiable elements; GCC's GIMPLE uses the same model (scalar SSA + explicit memory ops). Keeping [T] accesses as load/store ops with SSA scalars is therefore mainstream and defensible, and it lets affine-subscript dependence analysis read address arithmetic directly instead of reasoning about heap SSA.
14. Versions verified August 2026: cranelift-codegen, cranelift-frontend, cranelift-jit 0.135.0 published 2026-08-20, alongside simultaneous maintenance releases 0.134.4, 0.133.3, 0.123.14, 0.111.13 (wasmtime ships multiple support branches concurrently); docs.rs currently documents cranelift-frontend 0.134.x with API create_block(), append_block_param(), ins.jump(blk, &[args]), brif(c, blk_t, &[], blk_f, &[]), seal_block/seal_all_blocks, finalize().

## Recommendations

1. Implement CHK iterative idoms: iterative (explicit-stack) DFS for postorder to avoid recursion-depth crashes on deep chains, process in reverse postorder, iterate to fixpoint, intersect() via postorder-number finger walk. Reuse the resulting idom tree everywhere (CSE scoping, LICM safety checks, SSA verification) - one 80-line module pays for itself across the whole optimizer.
2. Derive DFs with the runner-walk rule (only needs the idom array), then build SEMI-PRUNED SSA: pass 1 collects per-block local-def sets and upward-exposed uses to classify global names; for each global name run the iterated-DF worklist over its def blocks (seeding def blocks with parameters/globals from the entry block); rename with a dominator-tree preorder walk and per-variable name stacks, filling phi args from each predecessor's current mapping.
3. Skip pruned SSA initially. Full block-level liveness is extra code and another fixpoint to maintain; add it only if profiling shows dead phis hurting later passes. Note in the project write-up that Braun et al. 2013 gives pruned SSA for free during AST-directed construction - good related-work material even though it does not fit an optimize-existing-CFG pipeline.
4. Keep SSA scalar-only: i32/i64/f32/f64/bool live in SSA values; arrays stay as explicit load/store/address ops (LLVM-style). Mark loads/stores as side-effecting for CSE/DCE by default; only the affine dependence analysis may reorder/parallelize them, and only after proving independence or recognizing a supported reduction (+,-,*,min,max).
5. Never translate out of SSA. Lower HELIX phis mechanically to Cranelift block params: one param per phi in a deterministic order recorded in a (block -> param order) table; every predecessor terminator reads that table to build its argument list. This deletes lost-copy handling, swap-cycle breaking, parallel-copy sequentialization, and edge-split-for-copies from your scope; Cranelift + regalloc2 own those problems.
6. Pin exact crate versions in Cargo.toml, e.g. cranelift-codegen/cranelift-frontend/cranelift-jit = "=0.135.0". Wasmtime publishes several maintenance lines on the same day, so caret ranges can silently resolve across divergent minors; exact pins keep the documented append_block_param/jump-args API stable.
7. Ship a debug-mode SSA verifier invoked after EVERY pass: (a) each use is dominated by its def (def block dominates use block; intra-block ordering respected); (b) every phi has exactly one argument per predecessor, mapped 1:1, types matching; (c) no use without a reaching def. Pair it with a differential tester: run optimized JIT output against the tree-walking interpreter on randomly generated programs - this catches optimizer bugs the static checker cannot.
8. Centralize all CFG mutation (block deletion, edge removal, unreachable-code cleanup) behind helpers that atomically update successor phis (drop the deleted pred's argument) and mark dominator info dirty. Recompute reachability and dominators after any CFG change before running any dominance-dependent pass.

## Pitfalls

1. Unreachable blocks corrupt everything downstream: CHK and iterated-DF phi placement assume a reachable-only flowgraph; an unreachable predecessor contributes bogus phi arguments. Strip unreachable blocks (forward reachability from entry) BEFORE dominator computation and again after every CFG-mutating pass.
2. Infinite loops / self-loops break naive postorder DFS: exit-less regions are unreachable from exits and blocks may never be visited; decide policy up front (reject or keep) and make the DFS mark unvisited nodes unreachable rather than dereferencing UNDEFINED idoms.
3. Entry-block sentinel: idom(entry) = entry itself; guard intersect() and DF walkers so they stop at the entry (entry has the largest postorder number) instead of looping or indexing out of range.
4. Uninitialized variables: renaming fabricates uses with no reaching def. Choose semantics (zero-initialize like cranelift-frontend's silent emit_zero, or diagnose as an error) and materialize an explicit init/undef value in the entry block so phis and the verifier stay well-formed.
5. Critical edges: classic phi-based SSA does not need edge splitting for PLACEMENT (phis are per-block), and block params naturally carry per-edge values; but you WILL need splitting if you ever insert code that must execute on exactly one edge (instrumentation, reduction epilogues, out-of-SSA copies). Splitting after phi insertion desynchronizes phi argument lists unless the args are migrated to the new intermediate block - either split before SSA construction or update phis atomically with the split.
6. The most common corruption bug: deleting an edge or block without deleting the matching phi argument (or adding a pred without adding an argument). One-sided updates survive until the next dominator query or Cranelift verification, making root-causing painful; route every CFG edit through one helper.
7. Loop-header phis interact badly with LICM: a header phi whose backedge operand differs from its entry operand encodes the loop-carried value and must never be hoisted, nor may its inputs move above the loop unsafely. Gate LICM on 'all operands defined outside the loop' and treat non-trivial header phis as immovable.
8. If anyone talks you into classical destruction anyway, budget for lost-copy (phi-split live ranges dying at inserted copies, classically in loops) and swap (parallel-copy cycles needing temporaries) - Sreedhar et al. SAS'99 / Budimlic et al. CGO'05 show this is a research-grade detour. This is precisely why phi-to-block-param lowering is recommended instead.
9. Cranelift argument-list discipline: adding/removing a block param without updating EVERY predecessor's jump/brif argument list fails late in Cranelift's verifier ('branch passes N arguments, destination expects M'). Generate both sides from a single table to prevent skew, and remember brif needs TWO independently correct argument lists.
10. Optimization boundary: once IR is lowered to CLIF you cannot run YOUR passes anymore - Cranelift applies only its own built-in optimizations (opt-level settings). Keep HELIX IR as the sole optimization substrate and treat lowering as one-way and last.
