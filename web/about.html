THE OBSERVATORY

One program. Eight views.

Each screen is a different question about the same compilation. Nothing is a decorative dashboard tile: the artifacts are the explanation.

  1. 01

    Source

    The HELIX language file, with line numbers and any compiler diagnostics attached to the original span.

  2. 02

    Tokens

    The lexer’s stream of keywords, identifiers, literals, and operators—the first machine-readable form.

  3. 03

    AST

    The parsed structure of the program, shown as a tree so nesting and expression shape stay visible.

  4. 04

    CFG

    Basic blocks and control-flow edges show where a function can branch, join, loop, and exit.

  5. 05

    SSA

    Static single assignment makes value flow explicit; φ-nodes mark where control-flow paths reunite.

  6. 06

    Optimization

    Pass snapshots show which transformations changed the intermediate representation and by how much.

  7. 07

    Loop analysis

    The dependence battery checks RAW, WAR, and WAW relationships before classifying a loop as safe, a reduction, or sequential.

  8. 08

    Benchmark

    Named kernels attach their matching point from the recorded campaign, including raw samples and parallel efficiency. Custom source can request a bounded interpreter-only measurement; native speedups are never invented.

THE IMPORTANT PART

Parallelism is a proof obligation.

A loop is not parallelized because it looks repetitive. HELIX looks for loop-carried memory relationships. If iterations are independent, the result is SAFE. If an associative accumulator can be privatized and combined, the result is REDUCTION. If a dependence crosses iterations, HELIX keeps the loop SEQUENTIAL and names the reason.

USING THE PROJECT

A short tour for a reviewer.

1

Choose an example from the source index. Start with saxpy for a clear safe loop, or recurrence_reject to see refusal evidence.

2

Move through the pipeline keyboard. Graph views can be dragged, zoomed, and reset; SSA and optimization panes can be compared.

3

Use Custom source to submit a small program through /api/run. Diagnostics remain attached to the source when later stages are unavailable; a valid custom program can then request seven bounded interpreter samples from the BENCH screen.

4

Export a named artifact for an offline, self-contained report. The Rust observer is the canonical runtime; the Node server labels fixture-only responses.

A NOTE ON EVIDENCE

Beautiful output should make the compiler easier to question.

HELIX does not invent speedups, hide diagnostics, or turn an unavailable stage into a success. Its job is to make the compiler’s reasoning inspectable enough that a student, reviewer, or future maintainer can follow the path from code to decision.
